# 记忆

**统一 Harness 协议，版本 `2026-10-04`**

智能体会遗忘。会话结束时，会话中的对话也随之结束（[会话](sessions.md)），而 Harness 的指令由其所有者一次性写入，不会随智能体的工作而改变。因此，智能体在过程中学到的一切都会丢失：客户偏好邮件、团队上周的决定、上次奏效的流程。

在此版本之前，协议无处保存这些内容。想要记忆功能的产品，需通过记忆服务自身的 API 将其接入某个 Harness，沿用该服务对"这是谁的记忆"的定义，且无法说明谁可以读什么。

**记忆**就是保存这些内容的地方。它是一个命名的**记录**容器：一条事实、一则笔记、一个流程、其他人所谈论的某个人或某家公司。记录之间相互指向，这些指针就是唯一的图：什么由什么得出，一条事实关于谁。

记忆按树状排列，如同文件夹，因此一个记忆可以保存整个公司所知的内容，其下的另一个记忆则保存关于某个客户所知的内容。访问权限按记忆授予，子记忆继承父记忆的权限。

人和智能体在此面前地位相同。两者都是成员，都以相同方式被授予访问权限，也都无法触及未被授予的内容。任务进行中，智能体搜索其记忆，并通过工具向其中添加内容。搜索覆盖一个记忆及其下所有内容，并说明每个答案保存在何处，以便智能体知道下一步去哪里查找。

本章是 Harness 记忆子协议。它是可选的：服务器通过 `memories` 能力声明它，未实现它的服务器在所有类别上均合规。

## 1. 记忆是什么

UHP 不定义记忆如何派生。提取、排序、整合和存储属于记忆背后的系统，即**提供方**：厂商的记忆服务、图数据库、一个文件文件夹。本章定义 Harness 与提供方必须达成一致的三件事，仅此而已：

```
提供方          其自身的存储与智能        记忆如何派生和保存
UHP 记忆        本章                        记忆是什么、谁可以触及
                                            它、Harness 何时调用它
MCP             智能体持有的工具            智能体在一轮中如何调用它
```

- **对象。** 记忆是树中的一个节点。它持有**记录**，记录之间相互引用，并可以有子记忆。
- **访问。** 授权赋予某个主体在某个节点上的权限；该节点的后代继承此权限。
- **接缝。** Harness 在会话生命周期的四个时刻触及记忆（[§9.1](#91-会话做什么)），其中只有两个是智能体的选择。

> **为什么是树，而不是一组固定的作用域？**
> 各记忆产品各自命名自己的层级（用户、智能体、运行、应用、团队、项目），没有两份列表是一致的。层级是实现赋予树中某个位置的含义：协议承载树和继承关系，服务器可以自由地声明某个节点是组织，其下是客户。节点存在于访问权限不同之处，别无其他：当某个会话的记忆恰好被读取其父记忆的同一批主体读取时，它无需自己的节点。

## 2. 记忆对象

```json
{
  "id": "hmem_7c1e4b9a2d3f4e5a8b6c7d8e9f0a1b2c",
  "object": "memory",
  "name": "Sales",
  "description": "What the sales team knows: accounts and pricing decisions.",
  "parent_id": "hmem_0a1b2c3d4e5f60718293a4b5c6d7e8f9",
  "ancestors": ["hmem_0a1b2c3d4e5f60718293a4b5c6d7e8f9"],
  "restricted": false,
  "provider": "example",
  "privileges": ["read", "write"],
  "records": { "count": 412 },
  "children": { "count": 3 },
  "createdAt": 1790560000000,
  "updatedAt": 1790570094000
}
```

| 字段 | 类型 | 写入方 | 含义 |
|---|---|---|---|
| `id` | string | 服务器 | 对客户端不透明。自行生成 id 的服务器使用 `hmem_` 前缀（[架构 §3](architecture.md#3-object-model)）；记忆是已有树的服务器沿用该树的 id |
| `name` | string | 客户端 | 人类可读 |
| `description` | string | 客户端 | 此记忆保存什么，一两句话。智能体读取它以决定是否查看内部（[§6.1](#61-搜索找到位置然后智能体行走)），因此它是内容，不是装饰 |
| `parent_id` | string 或 null | 客户端 | 包含它的记忆；根节点上为 `null` |
| `ancestors` | array | 服务器 | 从根到父节点的 id，以调用者可见的范围为限。仅用于定位：读取一个记忆永远不会读取祖先的记录 |
| `restricted` | boolean | 客户端 | 为 `true` 时，祖先上的授权到此为止（[§3.2](#32-截断)） |
| `provider` | string | 客户端 | 哪个提供方保存此记忆的记录（[§10](#10-提供方)）。创建时设置，省略时从父记忆继承；服务器可以拒绝更改它 |
| `privileges` | array | 服务器 | 调用者在此节点上的有效权限 |
| `records`、`children` | object | 服务器 | 计数，供调用者决定去哪里查找 |

| 请求 | 作用 |
|---|---|
| `POST /v1/memories` | 创建记忆：`name`、`description`、`parent_id`、`restricted`、`provider` |
| `GET /v1/memories?parent={id}` | 某记忆的直接子记忆，分页。不带 `parent`：调用者进入树的位置 |
| `GET /v1/memories?granted=true` | 调用者被授予的内容：它被允许进入的位置，以及其下它可以做其他事情的位置 |
| `GET /v1/memories/{id}` | 一个记忆 |
| `PUT /v1/memories/{id}` | 重命名、描述、限制它，或通过给出新的 `parent_id` 移动它 |
| `DELETE /v1/memories/{id}` | 删除该记忆、其记录及其后代 |

列表是一层。不带 `parent` 时，它回答调用者进入树的位置：它持有权限但其父不可见的每个记忆，因此被授予一个分支的调用者从该分支进入。想要子树的客户端逐层询问，或传入 `ancestor={id}` 以获取它可以读取的每个后代。服务器不得返回调用者没有有效权限的记忆，也不得透露其存在。

调用者进入的位置和它被授予的内容是两个问题。读取一个记忆并写入其某个子记忆的调用者从父记忆进入，而列表不显示该子记忆：它是一层。`granted=true` 在一个请求中回答第二个问题：调用者可以读取但其父不可见的每个记忆，以及这些记忆之下其可做之事与父记忆不同的每个记忆，各自附带调用者在那里的权限，树中位置最高的在前。它以调用者可做什么来表述，从不以服务器如何保存访问权限来表述，因此无论调用者是通过自己的授权、通过组还是通过角色被允许进入，答案都相同。客户端从中读取调用者可以在哪里写入而无需遍历树，智能体的工具也由此构建（[§9](#9-智能体及其记忆)）。

## 3. 访问

### 谁对记忆操作

一套词汇命名所有可以对记忆操作的主体。它用于两处：授权命名谁可以操作，记录的 `written_by` 命名谁操作了。

| 种类 | 谁 | 持有授权 | 写入记录 |
|---|---|---|---|
| `member` | 任何操作者：一个人或一个智能体 | 是 | 是 |
| `group` | 服务器解析的一组成员：一个团队、一个工作区 | 是 | 否，其成员写入 |
| `provider` | 记忆的提供方本身：它从观察中派生的内容、整合运行得出的结论 | 否 | 是 |

**人和智能体是同一种类。** 两者都是成员，以相同方式被授予、以相同方式被检查，并能属于相同的组。成员是两者中的哪一种，是成员的属性 `type`：`human` 或 `agent`。它供想知道的读者参考，本章没有任何规则依赖它。服务器对待智能体的组成员身份与对待人的完全相同：任何把新人加入组的操作也会把新智能体加入，别无其他。

服务器自有的种类以 `x.` 为前缀（`x.team`）。服务器不得使用另一个无前缀的种类，并拒绝命名此类种类的授权。

两处用两种方式写同一身份。在授权中，**主体**是字符串 `<kind>:<id>`。在记录上，写入者是 `{ "kind": …, "id": …, "type": … }`。它们命名同一事物：`written_by.kind` 和 `written_by.id` 用冒号连接，就是授权会命名的主体。`id` 是服务器自有的，对客户端不透明。

凭证不是种类，Harness 也不是。用 API 密钥发出的请求以该密钥所属的成员身份行事。Harness 是一种配置；其智能体是成员，服务器说明是哪一个（[§9](#9-智能体及其记忆)）。

### 3.1 授权与继承

**授权**赋予一个主体在一个记忆上的一组权限。主体在某个记忆上的有效权限，是它在该记忆及每个祖先上的授权之并集。访问是累加的：没有拒绝，没有授权即无访问。创建记忆者持有其全部四项权限，这是一个隐式授权，像其他授权一样向下流动。

| 权限 | 允许 |
|---|---|
| `read` | `recall`、`get`、`list`、`history`，运行标记为 `read` 的命名查询 |
| `write` | `observe`、`remember`、`revise`、`forget`，定义命名查询 |
| `create` | 创建子记忆 |
| `delete` | `erase`，删除记忆，更改其授权 |

| 请求 | 作用 |
|---|---|
| `GET /v1/memories/{id}/grants` | 谁在此记忆上持有什么，以及每个授权位于哪个节点 |
| `POST /v1/memories/{id}/grants` | 授予主体权限：`{ principal, privileges }`，主体为 `<kind>:<id>` |
| `DELETE /v1/memories/{id}/grants/{grant_id}` | 撤销一个授权 |

### 3.2 截断

`restricted: true` 的记忆停止继承：其祖先上的授权不触及它或其后代，它自己的授权照常向下流动。这是唯一的覆盖。服务器应将保存某人私有记录的记忆创建为受限。

### 3.3 强制执行

访问由服务器在每次操作上强制执行，模型无法选择、扩大或绕过。提供方通过将每个记忆保存在自己的容器中，或通过服务器在每次读写时添加的条件来隔离记忆；它声明是哪种（[§10.2](#102-能力文档)）。由智能体应用的过滤器，或智能体编写的查询可以省略的过滤器，不是强制执行。

## 4. 记录

记录是记忆持有的一个事物。其 `id` 是提供方的，对客户端不透明。

```json
{
  "id": "hrec_3b9f2a71c4d84e0f9a6b5c4d3e2f1a0b",
  "object": "memory.record",
  "memory_id": "hmem_7c1e4b9a2d3f4e5a8b6c7d8e9f0a1b2c",
  "type": "fact",
  "title": "Acme renews in March and wants its discount kept",
  "content": [
    { "type": "text", "text": "Acme renews in March and wants its discount kept." }
  ],
  "attributes": { "account": "acme" },
  "version": 2,
  "status": "active",
  "supersedes": 1,
  "time": {
    "valid_from": "2026-09-30T00:00:00Z", "valid_to": null,
    "written_at": "2026-10-01T17:02:11Z", "invalidated_at": null
  },
  "written_by": { "kind": "member", "id": "chrn_41c0", "type": "agent" },
  "references": [
    { "rel": "derived_from", "memory_id": "hmem_…", "record_id": "hrec_…" }
  ],
  "trust": "untrusted"
}
```

| 字段 | 含义 |
|---|---|
| `type` | 记录的种类（[§4.1](#41-类型)） |
| `title` | 命名记录的一行：文档的标题、实体的名称、事实的陈述。可选，最多 300 字符。搜索将其与内容一起匹配。没有标题的记录以其内容的开头命名 |
| `content` | 记录所说的内容：有序的部分列表，文本和文件（[§4.3](#43-内容)）。当记录有标题时可以为空：一条事实常常只有一句话 |
| `attributes` | 结构化字段。核心类型自由形式；扩展类型使用该类型的 schema（[§8](#8-类型)） |
| `version`、`status`、`supersedes` | 更改会追加一个版本并关闭前一个（[§5.3](#53-没有任何内容被覆盖)）。`version` 从 1 计数，`supersedes` 是它所替换版本的编号，第一个为 null；记录跨版本保持其 `id`。`status` 为 `active`、`superseded` 或 `forgotten` |
| `time` | 它在世界中何时为真（`valid_*`）以及记忆何时持有它（`written_at`、`invalidated_at`）。没有有效期的提供方将 `valid_*` 留为 null |
| `written_by` | 谁写入的，`{ kind, id }`，使用 [§3](#谁对记忆操作) 的词汇，由服务器从已认证的调用者盖章；客户端无法提供。当提供方写入时，另有两个字段说明原因：`on_behalf_of`，其观察所派生的主体，以及 `consolidation_id`，得出结论的运行（[§9.2](#92-整合运行)） |
| `references` | 此记录指向的其他记录（[§4.2](#42-引用)） |
| `follows` | 仅出现在服务器从记忆之外保存的来源派生的记录上：该来源的 `{ kind, id, name }`。此类记录不通过记忆修订或遗忘（[§5.4](#54-跟随来源的记录)） |
| `trust` | 读取时始终为 `untrusted`：记忆返回的是数据，从不是指令（[§13](#13-安全)） |

### 4.1 类型

每个服务器都理解的核心类型：

| `type` | 是什么 |
|---|---|
| `episode` | 到达时的原始经验：一轮对话、一份记录、一个动作及其结果、一份文档。仅追加 |
| `fact` | 一件值得记住的事，如其所述 |
| `note` | 智能体或人编写并维护的文档 |
| `procedure` | 带有其适用情境的操作指南 |
| `link` | 指向保存在别处之物的指针：一个地址和一段描述，没有自己的内容 |
| `entity` | 记录所关于的事物：一个人、一家公司、一个产品、一个地点。其 `title` 是其名称；其内容是已知的关于它的信息 |

任何其他类型都是扩展（[§8](#8-类型)）。服务器必须原样携带它不理解的类型的记录，且不得因此拒绝读取。

### 4.2 引用

引用通过 `memory_id` 和 `record_id` 命名一个记录。两端不必在同一记忆中，也不必在同一提供方。

- 引用在**读取**时以读取者的权限解析。对目标记忆没有 `read` 的读取者收到 `{ "record_id", "available": false }`，别无其他：不是引用的含义，也不是它所通向记忆的 id，因为命名该记忆就等于说它存在。
- 修订者设置它能看到的引用。被显示为不可用的引用，它既不能重述也不能移除：服务器在该调用者的修订中保持其原样。
- 写入引用不需要对其目标有 `read`。从私有记忆提升到共享记忆的记录保留其来源，只有可以读取来源的人才能跟随它。

**记录和引用就是图。** 没有用于实体和关系的第二结构：记录是节点，引用是从持有它的记录到它所命名记录的边。`rel` 说明边的含义。五个名称有定义的含义；任何其他名称原样携带。

| `rel` | 从 | 到 | 含义 |
|---|---|---|---|
| `derived_from` | 任何记录 | 它所来自的记录 | 来源：这由那得出 |
| `part_of` | 任何记录 | 它所属的记录 | 结构：文档的一节、对话的一轮 |
| `about` | 任何记录 | 一个 `entity` | 此记录关于该实体 |
| `subject` | 一个 `fact` | 一个 `entity` | 该事实所说的主体 |
| `object` | 一个 `fact` | 一个 `entity` | 它将主体关联到的对象 |

因此，两个实体之间有所陈述的关系是一个带有 `subject` 和 `object` 的 **`fact`**："Dana 是 Quillon Freight 的采购主管"是一条事实，其主体是实体 Dana，其对象是实体 Quillon Freight。作为记录，它具有每个记录都有的东西：写入者、为真的时间、历史、被更正和遗忘的方式，以及指向其所来自对话的自己的 `derived_from`。客户端可以将这样一条事实画成其两个实体之间的一条线，用事实的文本或其 `attributes.predicate` 标注。没有陈述的关系，例如一节属于其文档，是一个裸引用，无需自己的记录。

一个记录最多命名一个 `subject` 和最多一个 `object`。关于两个主体的陈述是两条记录；服务器以 `memory_invalid` 拒绝命名第二个任一者的记录。

提供方保存它拥有的实体和关系，不多不少（[§10.2](#102-能力
