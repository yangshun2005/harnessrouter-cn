# 安全注意事项

**统一 Harness 协议，版本 `2026-10-04`**

UHP 服务器运行的 agent 会执行工具、写入文件，并持有提供商凭证，而这一切是代表一个它从未见过的调用方进行的。这比模型端点的爆炸半径更大，因此这里将各项要求集中在一处，便于实现者逐项核对，而不必自行重新发现。

其他章节中已陈述的要求在此处重复，而非仅作交叉引用。一条需要读者从六个章节中拼凑出来的安全规则，就是一条会被遗漏的规则。

## 1. 凭证

- 服务器必须对除 `GET /v1/uhp` 之外的每个端点进行身份验证
  （[生命周期 §2](lifecycle.md)）。
- 服务器不得以让调用方能够枚举有效令牌的方式区分"无此令牌"与"令牌在此处不被允许"。
- 服务器不得在任何响应体、错误消息、事件、日志行或构建产物中回显凭证——无论是调用方的还是提供商的。
- 服务器应支持撤销凭证，且撤销必须对新请求立即生效。

### 1.1 提供商凭证

服务器用于访问模型提供商的凭证是系统中最有价值的机密，而 agent 自身的沙箱是系统中最不可信的地方：agent 可能被诱导读取其环境并将其打印出来。

- 服务器不应将提供商凭证放置在 agent 工具可读取的位置。
- 必须向 harness 提供凭证的服务器应签发短期、单会话的凭证，且必须能够独立于底层密钥将其撤销。
- 服务器不得在未根据配置的允许列表进行验证的情况下，接受调用方为代理请求提供的上游 URL。未经验证的上游会使服务器变成一个自带凭证的 SSRF 代理。

## 2. 对象作用域

- 每个对象——harness、响应、会话、容器、文件——都必须限定在创建它的主体范围内。
- 对调用方作用域之外对象的请求必须返回 `404`，绝不能返回 `403`。`403` 会确认该 id 存在，而这正是枚举攻击者想要的
  （[架构 §5](architecture.md)）。
- 作用域必须在每个操作上强制执行，而不仅在读取时。取消、删除、继续和下载都是对象访问。

> 一致性测试套件无法用单个凭证完全验证这一点。实现者应使用两个主体运行等效检查：以 A 创建对象，然后以 B 尝试对其执行每个操作，并确认每个操作都返回 `404`。

## 3. 构建产物是受攻击者影响的内容

agent 可能被说服写入一个具有选定内容和选定名称的文件。所有提供构建产物的服务都必须将其视为敌意内容。

- 构建产物下载必须附带 `X-Content-Type-Options: nosniff`。没有它，一个名为 `x.html` 的构建产物就会变成针对客户端自身源的存储型 XSS
  （[文件 §3](files.md)）。
- 构建产物应从与控制台或应用 UI 不同的源提供，这样即使注入成功也无法触及第一方 cookie 或存储。
- 服务器不得允许 `container_id` / `file_id` 对寻址其容器之外的任何内容。通过构建产物 id 进行路径遍历是 UHP 实现中最可能出现的严重漏洞；一致性测试套件会探测它（X-08），而通过该探测只是底线，并非证明。
- 服务器应限制每个会话的构建产物大小和数量。

## 4. 提示注入属于客户端的职责范围

读取网页、仓库或上传文件的 harness 可能会遇到针对它的指令。UHP 无法阻止这一点，而一个假装能阻止的规范会比一个坦率承认的规范更糟。

协议确实提供的、且客户端应使用的手段：

- **已配置 harness 上的 `disabledTools`**——能完成任务的最小工具集就是最小的注入面。
- **`max_step` 和 `timeout_seconds`**——有界任务无法被诱导为无界任务。
- **为不同信任级别使用不同的 harness。** 读取不可信输入的 harness 不应与持有特权工具或 MCP 服务器的已配置 harness 相同。
- **事件流。** 工具调用在发生时可见；客户端可以将其呈现或加以门控。

服务器不得声称以上任何一点能让 agent 安全地指向不可信输入。

## 5. 资源耗尽

- 服务器必须限制任务时长，且当预算中止了工作时必须报告 `incomplete` 而非 `completed`（[生命周期 §3](lifecycle.md)）。
- 服务器必须拒绝同一会话中的第二个并发任务（`session_busy`）——一个工作目录中有两个 agent 不是已定义的状态，而且也是廉价地倍增成本的方式。
- 服务器应按主体对任务创建进行速率限制，并应通过 `rate_limit_error` 响应暴露剩余预算，而非以不透明的方式失败。
- 服务器必须限制上传大小并以 `file_too_large` 拒绝，而非截断。被静默截断的输入会产生一个自信但错误的答案。

## 6. 数据处理

- 会话构建产物和记录在会话删除后必须不可访问。
- 服务器应记录其保留期限。"无限期"是一个答案；沉默不是。
- 会话共享（在实现的情况下）必须是只读且可撤销的，且不得暴露凭证或其他主体的数据（[会话 §5](sessions.md)）。

## 7. 传输

- 除回环外必须使用 TLS。
- 服务器应发送 `Strict-Transport-Security`。
- 提供任何 HTML 的服务器必须发送 `X-Frame-Options: DENY` 或等效的 `frame-ancestors 'none'` 策略。

## 8. 错误卫生

- `error.message` 必须可安全展示给用户：不含凭证、内部主机名、文件路径或堆栈跟踪（[错误 §1](errors.md)）。
- 服务器应记录其保留的细节，并附上在 `error.detail` 中返回的关联 id，以便运维人员诊断调用方看不到的问题。

## 9. 插件是第三方代码

插件（[插件](plugins.md)）是由安装它的运维人员之外的人编写的指令和可执行文件。安装插件即将其作者的信任扩展到 harness。

- 插件声明的 stdio MCP 服务器必须在运行 agent 的沙箱内运行，具有 agent 的权限且不多于此。它不得在服务器主机上运行，且不得通过 shell 启动。
- 服务器只能展开 `${PLUGIN_ROOT}` 和 `${PLUGIN_DATA}`，且仅在 `args`、`env` 和 `cwd` 中，不得执行任何其他占位符或环境变量展开。一个能将沙箱环境读入自身进程参数的插件，会读取沙箱持有的任何凭证（[§1](#1-credentials)）。
- 解析到插件根之外的 `command` 或 `cwd` 是无效条目，绝不允许（[插件 §6](plugins.md#6-running-with-plugins)）。
- 插件由管理 harness 的人安装（Full 类），绝不按请求安装。按请求的插件会变成按请求的 MCP 服务器，而 [任务 §1.4](tasks.md#14-reserved-fields-tools-and-include) 已出于同样原因拒绝此做法：收窄是安全的，放宽是提权。
- 插件内的技能是提示内容，受 [§4](#4-prompt-injection-is-in-scope-for-the-client) 约束。客户端应在安装前展示清单的 `author`、`homepage` 和 `repository`，并在安装后展示 `skipped`，以免未加载的内容被误认为已加载。
- 服务器必须在导出的包中省略 `auth` 和 `headers`（[插件 §5](plugins.md#5-exporting-a-harness-as-a-plugin)）。导出就是要离开。

## 10. 环境是共享的，且由所有者发送的内容构建

环境（[环境](environments.md)）会被每个引用它的会话读取，其构建会运行项目自身的清单和 `setup.sh`。由此得出三条规则：

- **只读是强制执行的。** 被告知不要写入的 agent 仍会尝试；服务器必须通过只读挂载、无权限用户或等效手段使写入失败，不得依赖该指令（[环境 §6](environments.md#6-what-a-session-sees)）。
- **构建具有任务的权限，而非服务器的权限。** 它以任务获得的工具链和网络运行，且不多于此；它无法读取另一个环境或任何会话。在多租户服务器上，它是拥有该环境的租户的任务（[环境 §9](environments.md#9-security)）。
- **路径在每个端点都被限制。** 文件路径、归档成员和仓库树都被限制在环境根内；指向根外的链接和绝对路径被丢弃，绝不跟随（[环境 §3](environments.md#3-files)）。

## 11. 记忆会在之后被他人读取

记忆（[记忆](memories.md)）在一个会话中写入，在另一个会话中由另一个 agent 为另一个人读取。由此得出三个特性，且没有一个可以留给 agent。

- **记忆返回的是不可信内容。** 一条记录可能由读过敌意页面的模型写入。服务器必须将召回的内容作为数据呈现给 agent，与指令隔离，并标明其作者（[记忆 §13](memories.md#13-security)）。
- **可达范围是 agent 的授权，在每次调用时。** agent 可以从其被附加的位置遍历树，搜索覆盖其所请求记忆之下的内容；它能到达什么由服务器根据授权决定，而非由 agent 请求什么决定，且它不可读取的记忆的应答与不存在的记忆完全相同。
- **提供商的凭证绝不进入沙箱。** 它属于连接提供商的人，由服务器在调用时使用（[§1](#1-credentials)）。

## 12. 报告漏洞

参考实现或本规范中的漏洞遵循私下披露，而非公开 Issue。请参阅仓库的安全策略。使安全实现无法达成的规范缺陷被视为漏洞，而非文档缺陷。
