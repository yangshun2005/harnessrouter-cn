# 安全注意事项

**统一 Harness 协议，版本 `2026-08-11`**

UHP 服务器运行的 agent 会执行工具、写入文件并持有提供商凭证，而这一切是代表一个素未谋面的调用方进行的。这比模型端点的爆炸半径更大，因此这里将各项要求集中在一处，方便实现者逐项核对，而不必自行重新发现。

其他章节中已陈述的要求在此重复列出，而不仅仅是交叉引用。读者需要从六个章节拼凑出来的安全规则，就是会被遗漏的规则。

## 1. 凭证

- 服务器必须对除 `GET /v1/uhp` 之外的每个端点进行身份验证（[生命周期 §2](lifecycle.md)）。
- 服务器不得以让调用方能够枚举有效令牌的方式区分"令牌不存在"和"令牌在此处不被允许"。
- 服务器不得在任何响应体、错误消息、事件、日志行或构建产物中回显凭证——无论是调用方的还是提供商的。
- 服务器应支持撤销凭证，且撤销必须对新请求立即生效。

### 1.1 提供商凭证

服务器用于访问模型提供商的凭证是系统中最有价值的机密，而 agent 自身的沙箱是系统中最不可信的地方：agent 可能被诱导读取其环境并打印出来。

- 服务器不应将提供商凭证放在 agent 工具可读取的位置。
- 必须向 harness 提供凭证的服务器，应签发短期、单会话的凭证，且必须能够独立于底层密钥撤销它。
- 对于代理请求，服务器不得在未根据配置的允许列表验证的情况下接受调用方提供的上游 URL。未经验证的上游会使服务器变成一个自带凭证的 SSRF 代理。

## 2. 对象作用域

- 每个对象——harness、响应、会话、容器、文件——都必须限定在创建它的主体范围内。
- 请求调用方作用域之外的对象必须返回 `404`，绝不能返回 `403`。`403` 确认了该 id 存在，而这正是枚举攻击者想要的（[架构 §5](architecture.md)）。
- 作用域必须在每个操作上强制执行，而不仅仅是读取。取消、删除、继续和下载都是对象访问。

> 一致性测试套件无法用单个凭证完全验证这一点。实现者应使用两个主体运行等效检查：以 A 创建对象，然后以 B 尝试对其执行每个操作，并确认每个操作都返回 `404`。

## 3. 构建产物是受攻击者影响的内容

agent 可能被说服写入具有选定内容和选定名称的文件。所有提供构建产物的服务都必须将其视为敌意内容。

- 构建产物下载必须附带 `X-Content-Type-Options: nosniff`。没有它，名为 `x.html` 的构建产物就会变成针对客户端自身源的存储型 XSS（[文件 §3](files.md)）。
- 构建产物应从与控制台或应用 UI 不同的源提供，这样即使注入成功也无法触及第一方 Cookie 或存储。
- 服务器不得允许 `container_id` / `file_id` 对寻址其容器之外的任何内容。通过构建产物 id 进行的路径遍历是 UHP 实现中最可能出现的严重漏洞；一致性测试套件会探测它（X-08），而通过该探测只是底线，不是证明。
- 服务器应限制每个会话的构建产物大小和数量。

## 4. 提示注入属于客户端的职责范围

读取网页、仓库或上传文件的 harness 可能会遇到针对它的指令。UHP 无法阻止这一点，而假装能阻止的规范会比坦承这一点的规范更糟。

协议确实提供了以下手段，客户端应加以利用：

- **已配置 harness 上的 `disabledTools`**——能完成任务的最小工具集就是最小的注入面。
- **`max_step` 和 `timeout_seconds`**——有界任务无法被诱导成无界任务。
- **为不同信任级别使用不同的 harness。** 读取不可信输入的 harness 不应与持有特权工具或 MCP 服务器的已配置 harness 相同。
- **事件流。** 工具调用在发生时可见；客户端可以将其展示或加以门控。

服务器不得声称以上任何一点能让 agent 安全地面对不可信输入。

## 5. 资源耗尽

- 服务器必须限制任务时长，且当预算中止工作时必须报告 `incomplete` 而非 `completed`（[生命周期 §3](lifecycle.md)）。
- 服务器必须拒绝同一会话中的第二个并发任务（`session_busy`）——同一工作目录中有两个 agent 不是已定义的状态，也是廉价地倍增成本的方式。
- 服务器应按主体对任务创建进行速率限制，并应通过 `rate_limit_error` 响应暴露剩余预算，而不是以不透明的方式失败。
- 服务器必须限制上传大小，并以 `file_too_large` 拒绝，而不是截断。被静默截断的输入会产生自信但错误的答案。

## 6. 数据处理

- 会话删除后，会话构建产物和记录必须不可访问。
- 服务器应记录其保留期限。"无限期"是一个答案；沉默不是。
- 会话共享（若已实现）必须是只读且可撤销的，且不得暴露凭证或其他主体的数据（[会话 §5](sessions.md)）。

## 7. 传输

- 除回环外必须使用 TLS。
- 服务器应发送 `Strict-Transport-Security`。
- 提供任何 HTML 的服务器必须发送 `X-Frame-Options: DENY` 或等效的 `frame-ancestors 'none'` 策略。

## 8. 错误卫生

- `error.message` 必须可安全展示给用户：不含凭证、内部主机名、文件路径或堆栈跟踪（[错误 §1](errors.md)）。
- 服务器应记录其隐瞒的细节，并附带在 `error.detail` 中返回的关联 id，以便运维人员诊断调用方看不到的问题。

## 9. 报告漏洞

参考实现或本规范中的漏洞遵循私下披露，而非公开 Issue。请参阅仓库的安全策略。使安全实现无法达成的规范缺陷被视为漏洞，而非文档缺陷。
