# 安全注意事项

**Unified Harness Protocol，版本 `2026-09-12`**

UHP 服务器运行的 agent 会执行工具、写入文件、持有提供商凭证，而这一切是代表一个素未谋面的调用方进行的。这比模型端点的爆炸半径更大，因此这里把各项要求集中在一处，方便实现者逐条核对，而不必自行摸索。

其他章节已陈述的要求在此重复列出，而非仅做交叉引用。一条需要读者从六个章节拼凑出来的安全规则，就是一条会被遗漏的规则。

## 1. 凭证

- 服务器 MUST 对除 `GET /v1/uhp` 之外的每个端点进行认证（[生命周期 §2](lifecycle.md)）。
- 服务器 MUST NOT 以让调用方能够枚举有效令牌的方式区分"无此令牌"与"令牌在此处无权使用"。
- 服务器 MUST NOT 在任何响应体、错误消息、事件、日志行或构建产物中回显凭证——无论是调用方的还是提供商的。
- 服务器 SHOULD 支持撤销凭证，且撤销 MUST 对新请求立即生效。

### 1.1 提供商凭证

服务器用于访问模型提供商的凭证是系统中最有价值的机密，而 agent 自身的沙箱是系统中最不可信的地方：agent 可能被诱导读取其环境并将其打印出来。

- 服务器 SHOULD NOT 将提供商凭证放在 agent 工具可读取的位置。
- 必须向 harness 提供凭证的服务器 SHOULD 签发短期、单会话的凭证，且 MUST 能够独立于底层密钥撤销它。
- 对于代理请求，服务器 MUST NOT 在未对照已配置的允许列表进行校验的情况下接受调用方提供的上游 URL。未经校验的上游会让服务器变成一个自带凭证的 SSRF 代理。

## 2. 对象作用域

- 每个对象——harness、响应、会话、容器、文件——MUST 限定在创建它的主体范围内。
- 请求调用方作用域之外的对象 MUST 返回 `404`，绝不返回 `403`。`403` 确认了该 id 存在，而这正是枚举攻击者想要的（[架构 §5](architecture.md)）。
- 作用域 MUST 在每次操作上强制执行，而不仅在读取时。取消、删除、继续和下载都是对象访问。

> 一致性测试套件无法用单个凭证完全验证这一点。实现者 SHOULD 用两个主体运行等效检查：以 A 创建对象，然后以 B 尝试对其执行每种操作，确认每次都返回 `404`。

## 3. 构建产物是受攻击者影响的内容

agent 可能被说服写入一个内容与文件名均由攻击者选定的文件。所有提供构建产物的环节 MUST 将其视为敌意内容。

- 构建产物下载 MUST 附带 `X-Content-Type-Options: nosniff`。否则，一个名为 `x.html` 的构建产物就会变成针对客户端自身源的存储型 XSS（[文件 §3](files.md)）。
- 构建产物 SHOULD 从与控制台或应用 UI 不同的源提供，这样即使注入成功也无法触及第一方 Cookie 或存储。
- 服务器 MUST NOT 允许 `container_id` / `file_id` 组合访问其容器之外的任何内容。通过构建产物 id 进行路径遍历是 UHP 实现中最可能出现的严重漏洞；一致性测试套件会探测它（X-08），而通过该探测只是底线，并非证明。
- 服务器 SHOULD 限制每个会话的构建产物大小和数量。

## 4. 提示注入属于客户端的职责范围

读取网页、仓库或上传文件的 harness 可能会遇到针对它的指令。UHP 无法阻止这一点，而一个假装能阻止的规范会比一个直言不讳的规范更糟。

协议确实提供、且客户端 SHOULD 使用的手段：

- **已配置 harness 上的 `disabledTools`**——能完成任务的最小工具集就是最小的注入面。
- **`max_step` 和 `timeout_seconds`**——有界任务无法被诱导成无界任务。
- **为不同信任级别使用不同的 harness。** 读取不可信输入的 harness SHOULD NOT 与持有特权工具或 MCP 服务器的已配置 harness 是同一个。
- **事件流。** 工具调用在发生时可见；客户端可以将其展示或加以门控。

服务器 MUST NOT 声称以上任何一项能让 agent 安全地指向不可信输入。

## 5. 资源耗尽

- 服务器 MUST 限制任务时长，且当预算中止了工作时 MUST 报告 `incomplete` 而非 `completed`（[生命周期 §3](lifecycle.md)）。
- 服务器 MUST 拒绝同一会话中的第二个并发任务（`session_busy`）——一个工作目录里有两个 agent 不是一种已定义的状态，而且也是廉价地成倍增加成本的方式。
- 服务器 SHOULD 按主体对任务创建进行限流，并 SHOULD 通过 `rate_limit_error` 响应暴露剩余预算，而非以不透明的方式失败。
- 服务器 MUST 限制上传大小并以 `file_too_large` 拒绝，而非截断。被静默截断的输入会产生一个自信但错误的答案。

## 6. 数据处理

- 会话删除后，会话构建产物和记录 MUST 不可访问。
- 服务器 SHOULD 记录其保留期限。"无限期"是一个答案；沉默不是。
- 会话共享（若实现）MUST 为只读且可撤销，且 MUST NOT 暴露凭证或其他主体的数据（[会话 §5](sessions.md)）。

## 7. 传输

- 除回环外 MUST 使用 TLS。
- 服务器 SHOULD 发送 `Strict-Transport-Security`。
- 提供任何 HTML 的服务器 MUST 发送 `X-Frame-Options: DENY` 或等效的 `frame-ancestors 'none'` 策略。

## 8. 错误卫生

- `error.message` MUST 可安全展示给用户：不含凭证、内部主机名、文件路径或堆栈跟踪（[错误 §1](errors.md)）。
- 服务器 SHOULD 记录其隐瞒的细节，并附上在 `error.detail` 中返回的关联 id，以便运维人员诊断调用方看不到的问题。

## 9. 插件是第三方代码

插件（[插件](plugins.md)）是由安装它的运维人员以外的人编写的指令和可执行文件。安装插件即把 harness 的信任扩展至其作者。

- 插件声明的 stdio MCP 服务器 MUST 在运行 agent 的沙箱内运行，且仅具有 agent 的权限，不得更多。它 MUST NOT 在服务器主机上运行，且 MUST NOT 通过 shell 启动。
- 服务器 MUST 仅展开 `${PLUGIN_ROOT}` 和 `${PLUGIN_DATA}`，且仅在 `args`、`env` 和 `cwd` 中展开，MUST NOT 执行任何其他占位符或环境变量展开。一个能把沙箱环境读入自身进程参数的插件，就能读取沙箱持有的任何凭证（[§1](#1-credentials)）。
- 解析到插件根目录之外的 `command` 或 `cwd` 是无效条目，绝不允许（[插件 §6](plugins.md#6-running-with-plugins)）。
- 插件由管理 harness 的人安装（Full 类），绝不按请求安装。按请求的插件就是按请求的 MCP 服务器，[任务 §1.4](tasks.md#14-reserved-fields-tools-and-include) 出于同样的理由已经拒绝：收窄是安全的，放宽是提权。
- 插件内的 skill 是提示内容，受 [§4](#4-prompt-injection-is-in-scope-for-the-client) 约束。客户端 SHOULD 在安装前展示清单中的 `author`、`homepage` 和 `repository`，并在安装后展示 `skipped`，以免未加载的内容被误认为已加载。
- 服务器 MUST 从导出的包中省略 `auth` 和 `headers`（[插件 §5](plugins.md#5-exporting-a-harness-as-a-plugin)）。导出就是为了离开。

## 10. 报告漏洞

参考实现或本规范中的漏洞遵循私下披露，而非公开 Issue。参见仓库的安全策略。使安全实现无法达成的规范缺陷被视为漏洞，而非文档缺陷。
